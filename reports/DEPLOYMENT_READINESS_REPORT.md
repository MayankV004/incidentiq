## 2. Release Blockers (Must Fix Before Deploy)

1. **Production Docker Compose fails to build `ui` and crashes `incidentiq-api` on startup**
   - *Evidence:* Running `docker compose -p iiq-relcheck -f deploy/docker-compose.yml build` exited with code `1` at `ui` step `[ui 6/6] RUN pnpm build` (`ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` because host `ui/node_modules` is copied without `.dockerignore` or `CI=true`). Running the built `iiq-relcheck-incidentiq-api` container exited immediately (`Exited (1)`) with `ModuleNotFoundError: No module named 'dotenv'` (`deploy/docker-compose.yml:123` omits `python-dotenv`, `sqlalchemy`, `psycopg`, `alembic`, `litellm`, `langfuse`, `langchain-core`, `redis`, `asyncpg`). Furthermore, `deploy/docker-compose.yml` uses unpinned `pip install ...` instead of `pyproject.toml`/`uv.lock`, omits `postgres`, `redis`, `prometheus`, `grafana`, and `traffic-gen` required by `docs/10_DEPLOYMENT_AND_OPS.md`, and sets no healthchecks, restart policies (except `caddy`), or container memory/CPU limits.
   - *Fix:* Replace inline `dockerfile_inline` blocks with proper multi-stage `Dockerfile`s using `uv sync --frozen --no-dev` for Python services and `CI=true pnpm install --frozen-lockfile` + `pnpm build` (passing `NEXT_PUBLIC_API_URL` as a Docker `ARG`) for `ui`; add `postgres` (pgvector), `redis`, `prometheus`, and `grafana` services, healthchecks, `restart: unless-stopped`, and resource limits.

2. **Secret leak into Docker images via missing `.dockerignore` and hardcoded fallback secrets**
   - *Evidence:* No `.dockerignore` exists at repo root or `ui/`. Docker builds transferred `1.50 GB` context per Python service and `633.59 MB` for `ui`. Inspecting `iiq-relcheck-incidentiq-api` confirmed `/app/.env` (1680 bytes containing host API keys), `/app/incidentiq.db`, and `/app/.venv/` are baked into the container filesystem. Separately, `incidentiq/api/security.py:10,26` (`DEFAULT_API_KEY = "dev_local_secret_key"`) and `incidentiq/security/tokens.py:11,23` (`DEFAULT_APPROVAL_SECRET = "incidentiq_capability_secret_2026"`) fall back to public hardcoded secrets committed in git whenever env vars are unset (and `deploy/docker-compose.yml` does not pass `API_KEY` or `APPROVAL_TOKEN_SECRET`).
   - *Fix:* Add root `.dockerignore` and `ui/.dockerignore` excluding `.env`, `.env.*`, `*.db`, `.venv/`, `.git/`, `node_modules/`, `.next/`, and `logs/`. Remove default secret constants so `incidentiq-api` and `mcp-remediation` fail fast on startup if `API_KEY` or `APPROVAL_TOKEN_SECRET` is empty or unset.

3. **Frontend UI cannot authenticate to `/v1/*`, breaks approval actions, and bakes `localhost:8000`**
   - *Evidence:* `ui/lib/api.ts` and `ui/hooks/useIncidentStream.ts` never send `X-API-Key`, and browser `EventSource` cannot attach custom headers; all `/v1/*` API calls return `401` when auth is enabled, causing silent fallback to hardcoded fixtures. In `ui/components/tabs/LiveView.tsx:78,89`, `handleConfirmApproval` and `handleReject` return immediately because `approval?.approval_token` is always `undefined` (backend only exposes `approval_id`). `ui/.next/static/chunks/1t1sjggx9yjdm.js` contains hardcoded `http://localhost:8000` (from `ui/.env.local`), while `deploy/docker-compose.yml:153` sets runtime `NEXT_PUBLIC_API_URL=/v1` (ignored at `next build` time and, if baked in, would request `/v1/v1/...`). Also `budget_exceeded` is absent from `IncidentStatus` (`ui/types/api.ts`) and `LiveView.tsx`, `pnpm lint` fails with 11 errors/6 warnings, and `AgentTimeline.tsx`, `AbstainedPanel.tsx`, `EvaluationView.tsx`, and `ShopView.tsx` retain hardcoded placeholder strings/fake handlers.
   - *Fix:* Either proxy UI requests through Next.js Route Handlers (`/api/*`) injecting server-side `API_KEY` (and streaming SSE via `fetch` `ReadableStream`), or prompt for a demo key in UI and switch SSE from `EventSource` to `fetch` `ReadableStream`; pass `approval.approval_id` in `LiveView.tsx`; set `NEXT_PUBLIC_API_URL=""` (same-origin) via build-arg; render `budget_exceeded` and remove all hardcoded text/fixtures; fix ESLint errors.

4. **`MCP_MODE=http` breaks replay scenario isolation and causes false diagnoses/approvals**
   - *Evidence:* `incidentiq/api/main.py:196` sets `os.environ["SCENARIO_ID"] = scenario_id` only inside the API process. In `MCP_MODE=http`, `mcp-metrics` (`mcp_servers/metrics/server.py:23`) and `mcp-logs` (`mcp_servers/logs/server.py:22`) run in separate processes/containers pinned to startup `SCENARIO_ID` (`001_orders_db_pool_exhaustion`), and `metrics/server.py` does not verify `metrics.json` matches the requested `service`. In our Gate 7 HTTP smoke test, ambiguous scenario `006_ambiguous_transient_noise` (`gateway`) and a poisoned alert on `006` both read `001` metrics and falsely diagnosed `db_pool_exhaustion` (`awaiting_approval`) instead of abstaining. Additionally, `os.environ["SCENARIO_ID"]` is never cleared when `scenario_id=None`, leaking state between replay and live incidents.
   - *Fix:* Pass `scenario_id` explicitly (or a `mode`/`scenario_id` parameter) as an optional tool argument / per-request context in `mcp_client.py` and MCP server tool signatures (validated with `validate_scenario_id`), and validate that replay `metrics.json["service"] == service` (or handle cross-service lookups explicitly).

5. **Caddy reverse proxy lacks TLS, basic auth, security headers, size limits, and SSE unbuffering, and breaks IP rate limiting**
   - *Evidence:* `deploy/Caddyfile:1-25` binds `:80` only (`no automatic HTTPS`), has no domain/TLS block, no `basicauth` on `/metrics` or admin UIs, no security headers (`HSTS`, `X-Content-Type-Options`, `X-Frame-Options`), no `request_body` size cap, and no `flush_interval -1` on SSE `/v1/incidents/*/stream`. Meanwhile `incidentiq/api/security.py:85` reads `request.client.host` without trusted proxy headers (`X-Forwarded-For`), so behind Caddy all internet visitors share Caddy's Docker bridge IP and trip the 5 req/min creation limit collectively.
   - *Fix:* Configure `deploy/Caddyfile` with the demo domain for automatic HTTPS, security headers, `request_body { max_size 64KB }`, `basicauth` on `/metrics` (and Grafana/Langfuse when added), and `flush_interval -1` for SSE; update rate-limit IP extraction to read `X-Forwarded-For` only when `request.client.host` is the trusted reverse proxy, backed by Redis instead of process-local memory.

6. **Daily cost cap bypassed on restart and budget/threshold env vars ignored**
   - *Evidence:* `incidentiq/api/main.py:533-537` computes daily spend solely from `INCIDENTS_DB.values()`, while `lifespan()` (`main.py:59`) only pre-warms `awaiting_approval`, `queued`, and `running` records—restarting the API container resets daily spend to `$0.00`. `incidentiq/agents/graph.py:17-18` hardcodes `MAX_AGENT_STEPS = 12` and `INCIDENT_BUDGET_USD = 0.05`, and `incidentiq/agents/nodes.py:482` hardcodes `confidence_threshold=0.50`, ignoring `.env` (`ABSTAIN_THRESHOLD`, `GROUND_THRESHOLD`, `INCIDENT_BUDGET_USD`, `MAX_AGENT_STEPS`, `REDIS_URL`, `MODEL_SMALL`, `MODEL_JUDGE` have 0 runtime reads from env). Also `stream_incident` (`main.py:642-649`) omits `"budget_exceeded"` from terminal states, causing SSE streams to hang indefinitely on `: ping` (verified in probe).
   - *Fix:* Query today's total `cost_usd` directly from the database (persisting real token-based LLM cost in `llm_calls`), wire `MAX_AGENT_STEPS`, `INCIDENT_BUDGET_USD`, `ABSTAIN_THRESHOLD`, and `GROUND_THRESHOLD` from `os.getenv`, and add `"budget_exceeded"` to `stream_incident` terminal statuses.

7. **Output prompt-leakage guard disconnected, incomplete PII redaction, and unvalidated API alert inputs**
   - *Evidence:* `GuardrailManager.scan_prompt_leakage` (`incidentiq/guardrails/guards.py:33-46`) is never called anywhere in `incidentiq/` (`output_guard_node` in `nodes.py:473-488` only calls `verify_groundedness`). `PII_PATTERNS` (`guards.py:6-10`) only matches 3 regexes; in our probe, `(555) 123-4567`, SSN `123-45-6789`, and `sk-proj-...` API keys persisted unredacted to SQLite. `POST /v1/incidents` (`main.py:529-603`) accepted `service="../../etc/passwd"` and `scenario_id="../../etc/passwd"` as well as `window_end < window_start` with HTTP `202 Accepted`.
   - *Fix:* Invoke `GuardrailManager.scan_prompt_leakage` in `output_guard_node` (quarantining/abstaining on hits), expand PII/secret redaction (Presidio + formatted phone, SSN, API key/Bearer patterns) across both `service` and `symptom`, and validate `service` (`ALLOWED_SERVICES`), `scenario_id` (`validate_scenario_id`), `symptom` max length, and `window_end > window_start` at `POST /v1/incidents` returning `400` in standard error shape.

8. **Broken Alembic lifecycle, zero telemetry DB writes, stub `/readyz`, non-compliant `422` errors, and missing backups**
   - *Evidence:* `migrations/versions/451ef2dd7538_add_telemetry_and_eval_tables.py` omits `incidents` while adding foreign keys to `incidents.id`, and running `alembic upgrade head` after `init_db()` (which runs on module import of `main.py`) crashes with `sqlite3.OperationalError: table approvals already exists`. Direct SQLite inspection after running incidents, PII/injection alerts, and remediation approval showed **0 rows** in `approvals`, `llm_calls`, `tool_calls`, `guardrail_events`, `eval_runs`, and `eval_results` (`repository.py` only writes `incidents`). `GET /readyz` (`main.py:165-167`) unconditionally returns `200 {"status": "ready"}` without probing DB or MCP servers. FastAPI `422` validation errors return `{"detail": [...]}` instead of `{"error": {"code", "message", "details"}}`. No backup script or log rotation exists.
   - *Fix:* Create a complete initial Alembic migration including `incidents` (and remove `Base.metadata.create_all` auto-DDL in production or stamp properly), persist rows to `llm_calls`, `tool_calls`, `guardrail_events`, and `approvals`, implement real DB/MCP probes in `/readyz` returning `503` on dependency failure, register a `RequestValidationError` and `Exception` handler for Doc 05 error envelopes, and add log rotation (`RotatingFileHandler` + Docker `logging` limits) and a `pg_dump` backup script.

## 7. Post-Deploy Checklist (First 30 Minutes) & Rollback Procedure

### Post-Deploy Checklist (Once Blockers Are Fixed)
- Verify DNS resolves to the VM public IP and `https://<domain>` serves a valid TLS certificate from Caddy.
- Confirm only ports `80` and `443` are reachable externally (`nmap` / external curl against `:8000`, `:8001`-`8004`, `:9101`-`9103`, `:5432`, `:6379` must time out or refuse).
- Verify `GET https://<domain>/healthz` and `GET https://<domain>/readyz` return `200`, and `GET /metrics` / admin panels prompt for Caddy basic auth (`401`).
- Verify `GET https://<domain>/v1/scenarios` returns `401` without `X-API-Key`.
- Run 1 replay scenario + dry-run approval end-to-end through the UI in a browser with zero console errors; verify `approvals`, `tool_calls`, `guardrail_events`, and `llm_calls` rows appear in Postgres.
- Trigger >5 incident creations/minute and verify `429 RATE_LIMIT_EXCEEDED` triggers cleanly; check `docker stats` and `docker compose logs --tail=50` for OOM/errors or leaked tokens/PII.

### Rollback Procedure
1. Immediately cut external demo access or disable LLM spend: revoke/rotate the LLM API key or set `DAILY_COST_CAP_USD=0` in `.env` and restart `incidentiq-api`.
2. Check out the prior known-good release tag/SHA on the VM (`git checkout <prev-sha>`), inspect `.env`, and rebuild/redeploy: `docker compose -f deploy/docker-compose.yml up -d --build`.
3. If an additive DB migration introduced issues, verify compatibility or run `uv run alembic downgrade -1` (after taking a `pg_dump` snapshot first).
4. Confirm `GET /readyz` returns `200` and execute one replay smoke check before re-enabling traffic.
